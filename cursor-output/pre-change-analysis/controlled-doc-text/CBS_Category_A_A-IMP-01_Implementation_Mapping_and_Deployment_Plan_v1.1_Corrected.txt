2. Purpose, Authority and Governance
This document converts the approved Category A target design into a controlled Salesforce implementation sequence.
The authoritative target state is CBS Category A Solution Design v1.4. Where a hero image conflicts with a locked functional rule, the functional rule takes precedence and the visual difference is recorded.
The latest metadata ZIP is authoritative evidence of the current technical state, not proof that existing behaviour is the desired target state.
Configuration changes begin only after this plan and the workstream pre-change impact report are approved.
UAT remains paused until a fresh metadata extraction and as-built reconciliation are approved.
Governance area
Controlled rule
Standard-first
Use standard objects, fields, validation, Flow, Flow Approval Processes, permissions, sharing, Files, Reports and Dashboards. Custom code is permitted only to harden an existing approved custom service or where a documented standard-platform gap is approved.
No silent scope expansion
Cursor and administrators must not introduce an unapproved object, field, route, role, automation, custom component or access path.
No destructive first deployment
Legacy fields, pages and permission assets are hidden, unassigned or deactivated first. Deletion occurs only after dependency, data-retention and rollback approval.
Separation of duties
Each deployment wave has a named implementer, checker and rollback authority.
Stop conditions
Stop immediately on a P1 privacy, cross-client isolation, self-approval, approval-bypass, data-loss or Contract/File exposure defect.

5. Technical Feasibility Decisions and Non-Negotiable Clarifications
Decision
Controlled implementation position
TD-01 Approval engine
Use Flow Approval Processes for Account onboarding, Client Access Request and final Quarterly Review approval where the org feature is available. The submitter field and assigned checker are explicit; recall is available only to the submitter or Approval Admin. Classic Approval Process is a controlled fallback only after a documented feature/edition gap and explicit approval.
TD-02 Quarterly scheduler
Salesforce schedule-triggered Flow does not run quarterly. Run CBS_Quarterly_Access_Review_Scheduler weekly and create the quarter record only when absent. Enforce a unique Review_Quarter_Key__c = AccountId + YYYY-Qn and a unique Review_Task_Key__c = ReviewCaseId + ContactId.
TD-03 Opportunity record type
Do not create a new Opportunity record type by default. Use the Master record type and a CBS Path/page assignment unless Wave 0 proves a record type is necessary. The hero label CBS Opportunity is visual context, not authority to add metadata.
TD-04 Opportunity-to-Contract traceability
Do not add a custom Opportunity lookup on Contract. Use Account as the standard relationship, the idempotent Closed Won follow-up Task and the Contract Number recorded in Task comments. The A-HERO-03 originating-Opportunity line is not an implementation requirement.
TD-05 Activated Contract immutability
Treat Activated Contract records as read-only for ordinary users. Renewal uses a new Contract; amendments use Files or a replacement Contract; termination follows the sandbox-verified standard action. Do not add Contract status values or a Contract approval process without an approved design amendment.
TD-06 Client User PII remediation
Do not bulk-delete identity data. Identify purpose, preserve backup/evidence, create or maintain a separate Data Subject Contact where required, clear prohibited Client User fields only after data-owner approval, and log every change.
TD-07 Cross-category Experience Cloud boundary
Remove generic object routes and prohibited administration routes only. Do not remove approved business routes owned by Categories B-F. Visibility and regression tests must preserve category-owned journeys while Category A pages remain restricted.
TD-08 External own-Contact access
Wave 0 must confirm the licence-supported sharing mechanism. Implement own-Contact-only access by the supported sharing-set or managed-sharing mechanism; never grant all Contacts under the Account.
TD-09 Audit capacity
Count selected fields per object before enabling history. Standard Field History Tracking is limited; use the purchased Shield Field Audit Trail policy only after Category H retention approval. No field is silently dropped from the approved catalogue.
TD-10 Source-design editorial precedence
In v1.4, stale statements that visual approval had not started are superseded by Section 18.15, the six-row approved hero register and the A-WS-08 closure decision.
