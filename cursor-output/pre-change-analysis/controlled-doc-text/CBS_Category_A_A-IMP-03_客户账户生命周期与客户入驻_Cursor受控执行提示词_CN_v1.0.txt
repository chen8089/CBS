2. 目的、范围与追溯关系
本文件是 Category A 工作流 A-IMP-03 的受控 Cursor 执行提示词。目标是在不改变现有业务数据的前提下，分析并准备基于标准 Account、标准 Task、声明式 Flow 与独立最终审批的客户账户生命周期和客户入驻实现方案。
2.1 本工作流范围
Account 客户生命周期值、入驻状态和状态转换控制。
Account 入驻字段、审计标记、系统受控字段和校验规则。
标准 Task 清单字段、Client Onboarding Task Type、当前周期与证据控制。
Start Onboarding、Task Synchronisation、Mark Ready / Submit、审批、退回 / 取消及完成通知的自动化设计。
只读验证 Opportunity、Contract、Salesforce Files、Client User Contact 和外部 User 前置条件。
现有 Account 基线分析、Client Code 重复清单与非破坏性整改计划。
必要的字段历史、持久化故障证据、部署顺序、回滚和 as-built 证据设计。
仅为技术测试所需的最小内部布局 / 动作暴露；最终 Lightning 页面设计仍属于 A-IMP-11。

7.6 强制业务控制
不得创建自定义 Onboarding 对象或自定义 LWC。
Account Name、Owner、唯一 Client Code、Notification Email 未完成，Account 为 Terminated，无 Closed Won Opportunity，或已有 active cycle 时，Start 必须被阻止。
每个批准清单项在 current cycle 只能存在一个 Task；创建逻辑必须幂等并能处理并发。若需要新 unique key field，必须停止并提交 Manifest amendment。
Mandatory item 03–08 在没有 non-sensitive evidence reference 时不得完成。
Business Development 通过 direct edit 不得把 Client Status 设置为 Active，不得把 Onboarding Status 设置为 Pending Approval / Completed，也不得写入 approval audit fields。
任何 current mandatory Task 未完成、progress 不一致、Opportunity / Contract / File evidence 缺失或 maker 等于 checker 时，Submit 必须阻止。
审批成功必须记录 approver 与 timestamp，将 Onboarding_Approved__c 设为 true、Onboarding Status 设为 Completed、Client Status 设为 Active。
Return 必须保留 approval history，并使 Account 继续不具备 access eligibility。
Cancellation 必须填写原因，并保持 approval false。
External user 不得读取 onboarding fields、Tasks、approval history、Opportunity、Contract 或 Contract File。
A-IMP-03 不得激活 User、分配 Permission Set 或修改 Experience Cloud sharing。
